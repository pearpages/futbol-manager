# ADR 0002 — Seeded PRNG: `sfc32`

**Status:** accepted · 2026-08-13

## Context

Almost everything uncertain in the game draws from a random source: scorelines (M2), injuries and training gains (M6), AI transfer decisions (M4), youth generation (M7). Ground rule 1 bans `Math.random()` in `domain`, and permits a seeded PRNG as the package's only dependency.

Three requirements drive the choice:

1. **Reproducibility.** M1's exit criterion is "deterministic under a fixed seed". When season 37 of a 50-season run produces a broken table, that exact run has to be replayable.
2. **Exact save/restore.** A player saves in February and reloads; March's fixtures must come from the same stream they would have. The generator's state therefore lives in the save file. `Math.random()`'s state is internal to the JS engine — unreadable and unrestorable — which disqualifies it outright, independent of seeding.
3. **Period headroom.** M6's day pipeline draws per player per day. Across ~500 players × 365 days × 50 seasons, draw counts reach the millions.

Candidates considered: `mulberry32` (32-bit state, period ~4.3×10⁹), `sfc32` (128-bit state, far longer period), and a library such as `pure-rand`.

## Decision

**`sfc32`**, hand-written in `domain`. State is four `uint32`s, serialised as a four-element array in the save file and restored exactly. No runtime dependency.

## Consequences

- M0's exit test — same seed → same sequence across serialise/deserialise — is satisfied by construction rather than by care, because the state is fully explicit.
- **Save-scumming is impossible by design.** Reload before a match and the result is identical. This is a game-design property that follows from the persistence requirement; if it is ever unwanted, it must be broken deliberately (e.g. by re-seeding on load), not by changing the generator.
- `mulberry32` was rejected on period headroom, not quality. A library was rejected to keep `domain` dependency-free; the ~10 lines are not the cost.
- **This is reversible only until the first save file exists.** After that, changing the algorithm invalidates every stored PRNG state and needs a migration that re-seeds — which changes the outcome of every in-progress career.
